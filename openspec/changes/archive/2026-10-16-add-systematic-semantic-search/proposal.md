# Proposal

## Why

Phase D can safely capture files but no public operation evaluates their passages. Phase E connects that foundation to the existing semantic parent/executor so systematic search reports actual processing coverage rather than mistaking one completed batch for a completed search.

## What Changes

- Add semantic_search with default/explicit systematic mode, closed predicate/scope/policy/run inputs, trusted session root and user-owned exclusions. Preparation without run captures but never classifies; invalid or unauthorized calls fail before acquisition.
- Reuse semantic-v1 and one shared parent/execution/results path for records and files. Scan every eligible captured window in deterministic path/range order with no lexical or semantic prefilter.
- Preserve immutable captured evidence, pinned models, decreasing invocation allowance, conservative charges, retries, cancellation/drain and generation expiry. Expose bounded continuation without implicit rescanning.
- Extend semantic results/evidence schemas for file identity, honest capture/processing coverage, plain captured snippets and explicit current-source checks. Record provenance remains unverified and unreadable.
- Retain the eight-parent/32-batch/shared8MiB bounds. Manage settled child resources so successful long searches are not artificially limited to32 retained completed children; preserve raw judgments, usage and retry lifetimes.
- Register eight tools total (three generic, five semantic) across all four family configurations. Public library exports/protocol stay unchanged.
- Verify vertical slices using user-confirmed tool/runtime/host seams, behavioral regression tests, real temporary Git/non-Git sources, fake providers, actual Pi/QuickJS and offline installed artifacts. Fix found bugs before moving on.

## Capabilities

### New Capabilities

- `systematic-semantic-search`: authorized safe file-search preparation, complete-or-explicitly-limited scanning, owned continuation, truthful coverage and bounded file result views.

### Modified Capabilities

- `toolkit-integration`: register systematic search and extend semantic evidence to captured files while preserving existing scenarios and family/usage behavior.
- `semantic-record-filtering`: explicitly scope the record-only evidence no-file-read guarantees while shared result operations also serve file parents.
- `safe-filesystem-evidence`: replace Phase-D-only registration restrictions with a model-independent capture boundary consumable by explicitly authorized search; retain every capture safety guarantee.

## Impact

Expected changes span src/semantic, src/pi owner/lifecycle/tool adapters, small capture snippet support in src/filesystem, tests, offline package verification and documentation. No new runtime dependency, second scheduler/memory pool, persistent evidence cache or semantic public library API. No live provider calls or publication are authorized. Discovery mode/targets/prioritization remain F; expansion/hashlines G; measured quality H; release readiness I. Reject unsupported inputs rather than silently acting like those phases exist.
